# Technical Interview Foundation Portfolio

## About

A reusable learning and interview-preparation portfolio focused on Python, SQL, troubleshooting, root cause analysis, AI-assisted development, graph investigation, and fraud / financial crime technology concepts.

The projects use simulated data and demonstrate small, explainable exercises. They do not establish professional experience, production operations, SAP/FICO product expertise, or validated fraud detection. The repositories are independent learning projects, not one integrated system.

## Foundation Projects

| Project | Description | Skills demonstrated |
| --- | --- | --- |
| [Python Data Troubleshooting](https://github.com/Lyon-Tan/python-data-troubleshooting) | Validate a transaction CSV and generate duplicate, invalid-record, and summary reports. | Python functions, sets, validation, exception handling, regression checks, and troubleshooting reasoning. |
| [SQL Data Investigation](https://github.com/Lyon-Tan/sql-data-investigation-lab) | Investigate synthetic customers, transactions, and payments with SQLite-compatible SQL. | JOINs, NULL handling, aggregation, CTEs, missing-record checks, and reconciliation. |
| [AI-Assisted Development](https://github.com/Lyon-Tan/ai-assisted-development-notes) | Document how to review and validate AI suggestions using a constructed debugging example. | Prompt design, code review, edge cases, security awareness, and responsible AI use. No live AI integration is implemented. |

## Specialisation

[Neo4j Fraud Investigation](https://github.com/Lyon-Tan/neo4j-fraud-investigation-lab) explores graph data and Cypher using fictional users, devices, transactions, and risk events. Queries cover shared-device analysis, linked-account investigation, bounded traversal, and fraud risk signals.

A shared device is an investigation lead, not proof of fraud. The lab has passed static syntax/data checks; live Neo4j execution remains unverified. It does not implement fraud scoring or AML detection.

## Role Mapping

| Business Systems Analyst | Expected-versus-actual behaviour and clear investigation scope; no stakeholder requirements project. |
| Data Analyst | Data quality, grouping, and reconciliation; no BI dashboard or statistical study. |

| Cybersecurity / IAM | Input validation and security-review habits; no IAM or authentication implementation. |
| Fraud Analyst | SQL discrepancies and graph links as leads; no real casework or confirmed fraud labels. |
| Financial Crime Technology | Explainable transaction and entity-link investigation; no AML system or regulatory reporting. |
